Access

Use your panel session in the browser. For scripts, send Authorization: Bearer <PANEL_API_KEY>. Node-agent examples use <NODE_API_KEY>.

Time fields

Use *_ts or UTC ISO fields for calculations and *_display for text shown to people. ttl_seconds and other durations never receive a timezone offset.

Testing

Change Settings → Panel → Regional, then verify /api/timezone, peer logs, subscriptions, public links, app logs, and Telegram without restarting the panel.

Regional time contract — source synchronized 2026-09-03. Settings → Panel → Regional is the single source of truth for every human-facing timestamp. Database values, epoch values, WireGuard handshakes, and canonical API ISO strings remain absolute UTC instants. Panel responses add the effective display_timezone and localized *_display fields where needed. Changing the saved IANA timezone changes display values immediately without rewriting stored data or restarting the service. Relative values such as ttl_seconds, “59m left,” and “2 hours ago” measure elapsed time and therefore do not change with the timezone.

Client endpoint precedence

Every code path that fills in a peer's client-facing endpoint — peer create, bulk create, config export, and the endpoint-default/apply routes below — resolves it in the same order: an explicit value on the request, then the interface's saved endpoint-default override, then auto-detection (the panel's configured domain or public IP, paired with the interface's listen port), then empty if none of those produce a value. This precedence lives in one place, resolve_client_endpoint, so nothing bypasses it.

Two fields carry endpoint data and must not be confused. Peer.endpoint is the client-facing server endpoint: the address the panel writes into the client's [Peer] block so the client knows where to dial. Peer.peer_endpoint is a fixed remote-client endpoint: written into the server's [Peer] block, and normally left empty because WireGuard learns a roaming client's endpoint from its first authenticated packet.

What it does

Creates a peer on a local interface (scope: "local", the default) or on a node (scope: "node" with node_id and iface_name).

Address. Omit address and the panel allocates the first free client address on the interface. The interface's own host address is never allocated, so no placeholder peer is needed. Supply address to pin one: it must be inside the interface network, of the same family, not the interface host, and not already in use. Invalid input returns 400 invalid_address; a taken address or an exhausted pool returns 409 address_conflict or 409 address_pool_exhausted. Endpoints. endpoint is this server's host:port, written into the client's config. Omit it and the peer now resolves through the interface's endpoint default at export time — its saved override, or auto-detection — instead of freezing whatever auto-detection returned at creation time, so a later change to the override or the auto-detected address is picked up automatically. peer_endpoint is an optional fixed endpoint for a non-roaming client and is the only value written into the server's [Peer] block; leave it empty unless you need it, because WireGuard learns a roaming client's endpoint from its first authenticated packet.

The response returns the address that was actually allocated, plus endpoint and peer_endpoint.

What it does

Reads the application log tail, parses recognized timestamps, normalizes each parsed instant to UTC in ts, and adds localized time_display with seconds. The top-level display_timezone identifies the saved IANA zone.
