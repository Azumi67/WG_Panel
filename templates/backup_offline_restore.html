PostgreSQL recovery Managed maintenance
Protected database restore

Database and Full restore replace the entire panel database, including all reseller accounts and customer records. The existing database and a recovery dump are retained.

Server settings stay in place

Full restore also recovers supported profiles, templates and endpoint settings. Credentials, encryption keys and bot configuration files stay unchanged. Local network recovery is optional.

PostgreSQL first, WireGuard second

Enable WireGuard recovery with a compatible Full backup. The panel verifies PostgreSQL, saves current network files and restores local configs and active peers before starting services. Interface keys, addresses, routes and hooks must match. Remote node configs require manual recovery. Without network recovery, backups missing current customers are rejected.

Automatic restart

Use the current administrator password and a trusted archive with matching encryption keys. Compatible schema differences are aligned in staging; incompatible tables or columns stop recovery. Older DB-only backups require you to confirm the keys. After temporary downtime, sign in with the restored credentials and check customer access.

Advanced recovery and logs

External PostgreSQL, Docker, server changes and remote node recovery require coordinated manual maintenance. Stop all writers, retain a recovery backup, and restore a trusted dump into a separate empty database.

pg_restore --exit-on-error --no-owner --no-acl --single-transaction --dbname=TARGET_DB dumpfile

Verify schema, records, keys and pending operations before activation. Preserve the original database.

journalctl -u 'wg-maintenance-restore-*' -n 200 --no-pager
