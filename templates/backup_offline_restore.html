PostgreSQL recovery Offline only

Database and full restores are disabled in the web panel. Settings-only restore is available.

  1. Stop the panel and all bot, provisioning and monitoring writers. Take a fresh backup of the current database.
  2. Inspect the archive and extract db/wgpanel-postgresql.dump to a private path.
  3. Provision a new empty PostgreSQL database with the correct permissions. Never restore over the live database.
  4. Use a matching or newer PostgreSQL client and run:
    pg_restore --exit-on-error --no-owner --no-acl --single-transaction --dbname=TARGET_DB dumpfile
    Replace TARGET_DB and dumpfile with the actual test target and path.
  5. While connected to the recovered database only, confirm the provisioning table exists and quarantine unfinished jobs before any worker starts:
    UPDATE rp_provision_job SET state='review', message='Restored operation; reconcile before resuming.', finished_at=NOW(), notify_after=NULL WHERE state IN ('queued','running');
    Never run this recovery command against the live working database. Verify records and WireGuard state, then switch the database URL only after successful validation.

Keep the original database, credentials and encryption keys. Full recovery instructions are also included in POSTGRESQL-MIGRATION.md in the source package.
